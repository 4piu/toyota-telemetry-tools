# Verify with J2534

## Inputs

- A working, correctly registered J2534 04.04 VIM and vendor DLL of known architecture.
- Captured protocol, flags, bitrate, filters, configuration, session, and request sequence.
- A byte-exact transmit allowlist and expected endpoints/responses.

## Procedure

1. Match client process architecture to the vendor DLL and verify exports before connecting.
2. Review the readiness-checked collection scope (`telemetry collect --dry-run`
   or the desktop Collect page) before confirming live collection.
3. Connect once, install the narrow receive/flow-control filters, and clear only relevant buffers.
4. Reproduce the smallest proven session and read sequence at the OEM cadence.
5. Log raw application payloads, timestamps, decoded values, negative responses, and cleanup status.
6. Disconnect and close on Ctrl+C, timeout, unexpected response, or transport error.

J2534 ISO15765 often performs segmentation and flow control inside the adapter. An application-managed ISO-TP mode over raw J2534 CAN is useful for distinguishing adapter/driver latency from gateway/ECU latency, but it must implement PCI validation, sequence numbers, timeouts, flow control, and padding correctly.

Successful independent acquisition raises the signal to Replayed. It does not prove a future CAN controller implementation; repeat through the intended backend.
